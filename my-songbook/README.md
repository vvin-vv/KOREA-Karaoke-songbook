# 나의 노래방 번호책 🎤 (v1.1.0)

아이폰 홈 화면에 추가해서 사용하는 **PWA 노래방 번호책**입니다.

## 주요 기능

- **POP / J-POP / 발라드** 장르별 필터 (저장된 노래를 별도 카테고리로 분류)
- 전체곡 검색 결과를 저장할 때 장르를 바로 지정하는 선택창
- 수동 추가와 편집에서도 장르 지정, 각 카테고리의 곡 수 표시
- 기존 백업의 `팝송` 장르도 자동으로 **POP** 분류에서 볼 수 있음
- **분류 기준:** POP = 해외 팝, J-POP = 일본 노래, 발라드 = 발라드. 나머지는 기타 카테고리 (K-POP, 록 포함)


- TJ / KY(금영) 제목·가수·노래번호 온라인 검색
- 검색한 노래의 번호를 내 노래책에 저장하고 즐겨찾기
- TJ와 KY 번호를 각각 보관
- 내가 부르는 키 / 장르 / 메모 / 다른 표기(일본어 독음 등) 기록
- 저장곡 검색 시 등록한 다른 표기로도 검색 가능 (외부 API의 일본어 음역 자동 변환은 미지원)
- 오프라인에서도 저장한 노래 열람·편집
- JSON 백업/가져오기 (iCloud Drive 등에 직접 저장)
- iPhone Safari 홈 화면 아이콘, 다크 테마

## 처음 사용할 때 — 웹에 올리기

**추천 배포: Vercel (무료 플랜으로 시작 가능, 이용 조건 확인)**

1. GitHub에서 새 저장소를 만들고 **이 폴더에 있는 파일들을 그대로** 업로드합니다. `public` 폴더와 `api` 폴더를 같은 최상위 위치에 두세요.
2. https://vercel.com/ 에서 로그인 → **Add New > Project** → GitHub 저장소 연결.
3. Framework Preset은 **Other**, Root Directory는 프로젝트 루트(`.`)로 설정합니다. 별도 빌드 명령은 없습니다. `public` 폴더의 정적 파일과 `api/search.js` 서버리스 함수를 배포합니다. 플랫폼이 출력 디렉터리를 요구하면 `public`로 지정합니다.
4. **Deploy**를 누르면 `https://...vercel.app` 형태의 주소가 생성됩니다.
5. 아이폰에서 **Safari**로 해당 주소를 열고, 공유 버튼 → **홈 화면에 추가** → **웹 앱으로 열기**(있는 경우) → 추가.
6. 앱을 열고 `신호등`처럼 곡명을 입력하여 검색 기능을 테스트합니다.

**왜 Vercel?** `api/search.js`는 외부 API 검색을 같은 출처(same origin)에서 중계해 Safari의 CORS 제한 문제를 우회합니다. Vercel이 아닌 단순 정적 사이트(GitHub Pages 등)에 올려도 저장 기능과 PWA는 작동하지만, 전체곡 검색은 외부 API의 CORS 허용 여부에 따라 작동하지 않을 수 있습니다. 따라서 검색까지 안정적으로 구현하려면 Vercel 배포를 권합니다.

### 설치 완료 여부 확인

- 아이폰 Safari에서 Vercel 주소를 연 뒤 **홈 화면에 추가**합니다.
- 홈 화면의 **노래책** 아이콘을 눌러 실행합니다.
- `TJ`와 `금영`을 바꿔가며 임의의 노래를 각각 검색해 번호가 나오는지 확인합니다.
- 마음에 드는 곡을 저장하고 **비행기 모드**에서 이미 저장한 번호가 표시되는지 확인합니다.
- 설정에서 **백업 파일 저장**을 눌러 iCloud Drive에 저장합니다.

### 로컬에서 화면 확인

`public/index.html`을 파일로 직접 열면 저장과 PWA 기능에 제약이 있을 수 있습니다. Node 18 이상에서 `npm run dev` 를 실행한 뒤 `http://localhost:4173`에서 확인하세요. 개발 서버는 외부 API 연결이 가능한 네트워크가 필요합니다.

## 데이터 보관

저장한 곡은 각 기기 브라우저의 **IndexedDB**에 보관합니다. 서버에 별도 계정을 만들거나 데이터를 업로드하지 않습니다. 단, 검색어는 외부 검색 서비스로 전달됩니다. 기기 간 자동 동기화는 없으며 Safari 데이터 삭제 시 노래책 데이터가 사라질 수 있습니다. 앱의 설정 > **노래책 백업 파일 저장**으로 JSON 백업을 내려받고 iCloud Drive에 저장하세요. 새 기기에서는 **백업 파일 가져오기**를 사용하세요.

## 외부 검색의 한계

전체곡 검색은 제3자 공개 서비스 API Manana (`https://api.manana.kr/v2/karaoke/search.json`)를 사용합니다. **TJ/금영의 공식 API가 아닙니다.** 서비스 정책·가용성·CORS·데이터 정확성/최신성은 변할 수 있습니다. 중요한 번호는 공식 반주곡 검색에서 재확인하세요.

- TJ 공식: https://www.tjmedia.com/song/accompaniment
- 금영: https://kysing.kr/search/

외부 검색 API는 장르를 제공하지 않으므로 **검색 결과를 장르별로 자동 분류하지 않습니다**. 노래를 저장할 때 직접 POP / J-POP / 발라드를 선택하세요.

API가 실패하는 경우 앱은 오류를 안내하고 공식 검색 링크를 제공합니다. 임의의 곡번호를 표시하거나 존재하지 않는 검색 결과를 만들어내지 않습니다.

## 파일 구조

- `public/index.html`: 화면
- `public/styles.css`: 디자인/모바일 레이아웃
- `public/app.js`: 검색, 등록, 즐겨찾기, IndexedDB, JSON 백업/복원
- `public/sw.js`: 오프라인 PWA 캐시
- `public/manifest.webmanifest`: 홈 화면 앱 설정
- `public/icons/`: 홈 화면 아이콘
- `api/search.js`: Vercel 서버리스 API 중계
- `dev-server.js`: 로컬 테스트 서버 (Node 기본 모듈만 사용)

## 개발 후 업데이트

UI나 스크립트를 수정해 배포할 경우 `public/sw.js`의 `CACHE` 값을 새 버전으로 바꿔 캐시를 갱신하세요. 데이터는 IndexedDB에 유지됩니다.

## 자동 테스트

Node.js 18 이상에서 `npm test`를 실행하면 정적 PWA 파일 구성과 서버 검색 요청·오류 처리를 테스트할 수 있습니다. 현재 자동 테스트는 **외부 검색 서비스를 직접 호출하지 않으며**, 아이폰 실기기 검증을 대체하지는 않습니다.

## 데이터 이용 주의

검색 API는 제3자 서비스가 제공한 곡번호 데이터를 사용합니다. 개인 사용 목적이라도 제3자 API의 라이선스·요청 제한·서비스 정책을 확인하고, 실제 반주기에서 최종 곡번호를 검증하세요.
